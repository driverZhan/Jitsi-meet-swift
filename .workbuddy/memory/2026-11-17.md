# 2026-11-17

## CocoaPods 改为二进制 pod 方案（用户指定思路）

把 11-16 的源码型 podspec 改为二进制方案，两个 podspec 分工明确：

- **JitsiMeetSDK.podspec（重写，v1.0.0）**：纯二进制 pod，只暴露 `dist/JitsiMeetSDK.xcframework`（静态，链接不嵌入）+ `dist/JitsiMeetSDK_JitsiMeetSDK.bundle`（经 `s.resources` 原样拷入宿主主包）。不再有 prepare_command/source_files/shim；.gitignore 的 PodSources/ 条目一并移除。
- **JitsiWebRTC.podspec（新增，v124.0.2）**：vendored `Frameworks/WebRTC.xcframework`（Jitsi 官方 M124 构建，iOS 12+ 动态框架），版本号即上游 tag；JitsiMeetSDK 以 `s.dependency 'JitsiWebRTC', '~> 124.0'` 引用。
- 资源查找原理已核实：dist 静态框架里编译进了 SwiftPM 的 `Bundle.module` 访问器（strings 可见 `JitsiMeetSDK_JitsiMeetSDK.bundle`），bundle 放 App 主包根目录即可命中，无需任何 shim。
- build-xcframework.sh 的 INTEGRATION.txt 补了 CocoaPods 接入段；宿主 Podfile 只需 `pod 'JitsiMeetSDK'`，JitsiWebRTC 自动带上。
- 验证（pod install + 产物检查，沙箱内完成）：依赖解析自动拉起 JitsiWebRTC；聚合 xcconfig 正确产出 `-framework JitsiMeetSDK -framework WebRTC` + 系统框架；JitsiWebRTC 有 Copy XCFrameworks 嵌入阶段（唯一 signed binary）；二进制 pod 无 umbrella/modulemap，无模块名冲突；资源 bundle 进入 resources 阶段。xcodebuild 编译验证仍受沙箱限制，建议真实终端跑一次 lint 收尾。
- 已知边界不变：二进制 swiftmodule 无 .swiftinterface，宿主 Xcode/Swift 版本需与打包一致；SDK 变更后先重跑 build-xcframework.sh 再抬 pod 版本。podspec 的 source/homepage/author 仍是占位值。
