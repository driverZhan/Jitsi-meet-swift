## CocoaPods 接入（JitsiMeetSDK.podspec）

- 新增 `JitsiMeetSDK.podspec`（源码型 pod，v1.0.0）：复用 build-xcframework.sh 的「拍平单模块」策略——prepare_command 把 7 个模块 44 个 swift 文件拷到 PodSources/、剥离跨模块 import（含 @_exported），排除 Demo/Tests；`.gitignore` 加了 PodSources/。
- 关键适配：CocoaPods 不生成 SwiftPM 的 `Bundle.module`，podspec 在 PodSources 里注入 `BundleModuleCompat.swift` shim（按 SwiftPM 命名 `JitsiMeetSDK_JitsiMeetSDK.bundle` 查找，静态/动态链接两处都覆盖），JSCEngineHost.swift 零改动；编译条件用自定义 `JITSI_SDK_POD`（SWIFT_ACTIVE_COMPILATION_CONDITIONS），避免依赖 SWIFT_PACKAGE 是否由 CocoaPods 定义。
- WebRTC.xcframework（iOS 12+ 动态框架）作为 vendored_frameworks 随 pod 接入；resource_bundles 保留 js/ 子目录与 SwiftPM 布局一致。
- 验证：pod lib lint 被 host 沙箱拦在 xcodebuild 清理阶段（DerivedData/TemporaryItems 删除被拒）；toybox shim sed 不支持 `sed -i ''`，prepare_command 已改为逐文件重写（可移植）。已验证：pod install 生成 45 个源文件引用、xcconfig 注入 JITSI_SDK_POD、资源 bundle target 与 js/ 分组结构正确；swiftc -typecheck 全部拍平源码仅剩 ControlBar.swift 的 SwiftUI 宏错误（沙箱拦 swift-plugin-server，环境问题）。真实终端上建议跑一次 `pod lib lint JitsiMeetSDK.podspec --allow-warnings` 收尾确认。
- podspec 的 s.source/homepage 是占位 URL，发布前需替换为真实仓库地址。
